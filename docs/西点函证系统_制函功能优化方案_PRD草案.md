## 一、背景与问题

### 1.1 现状

当前制函功能以「**数据导入（按科目）→ 模板 Output 函数取数 → 生成 PDF**」为核心模式，模板调整需进入 OnlyOffice 在线编辑 Word 模板，其中嵌入 `Output()` 函数和 `{{变量}}` 占位符。

### 1.2 用户反馈的两个核心诉求

| # | 诉求 | 本质 |
|----|----|----|
| 1 | **模板调整交互过于复杂**：要接触 Output 函数、{{变量}} 等类代码语法，无经验用户学习成本高、难以上手 | 制函模板调整"去代码化"，降低门槛 |
| 2 | **科目数据映射不够灵活**：希望给定模板后，用户自己在 Excel 中维护函面表格（自由定义几列/表头/数据），系统只负责把表格放到模板指定位置；一个函证多个表格=Excel 多个 Sheet，每个 Sheet 放哪也要可定义 | 把"函面如何呈现"的控制权从系统交还用户 |

### 1.3 方案目标

在**不破坏现有 Output 模式**的前提下，新增一种更友好的制函方式（Excel 直填），让无经验用户也能快速、灵活地完成制函。

## 二、核心方案总览

### 2.1 双模式制函

| 维度 | 模式 A：Output 函数（现有，保留） | 模式 B：Excel 直填（新增） |
|----|----|----|
| **适用人群** | 熟悉函数的老用户 / 复杂场景 | 无经验的新用户 / 常规场景 |
| **数据来源** | 系统控制表 + Output 取数 | 用户自己维护的 Excel |
| **表格结构** | 模板内固定列 | Excel 里自由定义列/表头 |
| **优势** | 数据与系统控制表联动、可跨函证复用 | 零学习成本、任意表格结构、所见即所得 |
| **劣势** | 门槛高、结构受限 | 数据需手动维护、与系统控制表解耦 |

> 两种模式**可混用**于同一份模板（详见 2.3 混用规则）。

### 2.2 统一模板处理引擎：OnlyOffice

- 模板的**编辑、Sheet 拖拽绑定、预览**统一在 OnlyOffice（Word 模板）内完成；
- **最终制函格式严格按原始 Word 模板**生成 PDF；
- **取消 Markdown 转换方案**（实测证明 docx→md 对宽表/复杂表格转换不理想，详见附录 A）。

### 2.3 模板内的双模式混用

- 同一份模板中，**部分表格用 Output 取系统数据，部分表格用 Excel 直填**（如"其他事项"等灵活内容用 Excel 更合适）；
- 制函入口**跟随模板类型**，不设全局模式开关——用户只需选模板，无需理解"模式"概念。

## 三、需求详述

### 3.1 制函流程

#### 3.1.1 标准制函流程（Excel 直填模式 / 新增）

```
进入「制函管理」Tab
   ↓
1. 某函证 → 上传/维护该函证对应的 Excel（含多个 Sheet）
   ↓
2. 为函证选择模板（模板已配好"Sheet↔模板表格"的拖拽绑定关系）
   ↓
3. 点击【PDF 格式制函】→ 勾选函证 →【确定】
   ↓
4. 系统：取该函证的 Excel → 按绑定关系把每个有数据的 Sheet 套进模板对应表格位置 → 生成 PDF
```

#### 3.1.2 模板配置流程（Excel 直填模板 / 低频）

```
进入「修改制函模板」/ 模板管理
   ↓
1. 从现有模板复制 / 新建模板（Word，OnlyOffice）
   ↓
2. 在 OnlyOffice 中拖拽，把模板的某个表格位置 与 某个 Sheet 建立绑定
   ↓
3. 保存模板（绑定关系持久化为模板级配置）
   ↓
4. 回到制函流程使用该模板
```

#### 3.1.3 Output 模式流程（现有，保持）

沿用现有「修改制函模板 → OnlyOffice 编辑 Output 函数/{{变量}} → 制函」流程，不改变。

### 3.2 数据模型

#### 3.2.1 数据组织层级

| 层级 | 内容 |
|----|----|
| **项目** | 一个审计项目，下含多个函证 |
| **函证（控制表）** | 一份函证 = 一份 Excel 的内容载体，Excel 内含多个 Sheet |
| **Sheet** | 函面上的一张表格（列数、表头、数据全部由用户在该 Sheet 里定义） |
| **模板位置** | 通过拖拽绑定，把 Sheet 放置到 Word 模板的某个表格/区块位置 |

#### 3.2.2 核心绑定关系

| 绑定 | 层级 | 说明 |
|----|----|----|
| **Sheet → 模板表格位置** | **模板级** | 同一模板的函证共用同一套绑定，做一次即可 |
| **Excel → 函证** | **函证级** | 每个函证各自的 Excel 内容 |

> 绑定关系分层是关键：模板配好一次绑定，之后每个函证只需上传自己的 Excel、选该模板即可制函。

#### 3.2.3 存储与实体关系

| 实体 | 关键字段 | 说明 |
|----|----|----|
| **制函模板**（format） | 模板 ID、Word 文件、类型（Output/Excel直填/混用） | 复用现有模板表 |
| **模板-Sheet 绑定** | 模板 ID、Sheet 标识、目标表格定位（如表格序号/书签/占位符 ID）、来源类型（Sheet/Output） | **模板级**，一张模板多条绑定 |
| **函证 Excel 附件** | 函证 ID、Excel 文件、多 Sheet 结构 | **函证级**，每函证一份 |
| **Sheet 数据** | 表头行、数据行、列结构 | 制函时从 Excel 解析 |

> **关键点**：绑定关系只存"哪个 Sheet/来源放模板哪个表格"，**不存具体数据**；数据在制函时从该函证的 Excel 实时解析，保证模板复用 + 各函证数据独立。

### 3.4 需求明细

#### FR-1：Excel 直填数据上传与维护
- 用户在函证下上传/维护一份 Excel（`.xlsx`），支持多 Sheet；
- 每个 Sheet 的**第一行为表头**，其下为数据行；列数、表头文本、数据内容均可自由编辑；
- 支持 Sheet 的新增、删除、重命名。

#### FR-2：模板级 Sheet 位置绑定（OnlyOffice）
- 在 OnlyOffice 模板编辑器中，用户可将某个 Sheet **拖拽绑定**到模板的某个表格位置；
- 绑定关系持久化为**模板级配置**，同模板所有函证复用；
- 支持查看/删除已有绑定；支持"一个 Sheet 绑定多个位置"；
- **绑定状态可视化**（详见 FR-6）：未绑定位置以虚拟表格占位 + 半透明标注；绑定后用颜色区分来源（Sheet=浅蓝、Output=浅黄）。

#### FR-3：制函渲染
- 制函时，系统按绑定关系，在模板的**占位锚点位置**，根据 Excel Sheet **动态生成完整表格**（列数 = Sheet 列数，表头 = Sheet 第一行，数据 = 其余行）；
- **空 Sheet 跳过**，不影响制函；
- **渲染规则**：**表头样式与模板样式一致**；**表格总宽度 = 函证模板文本宽度**（无论几列，总宽对齐文本区），列内分配详见 FR-7；
- **Excel 数据不校验**，完全按用户给的行列内容展示；
- 最终 PDF **严格按原始 Word 模板版式**生成；
- **不存在"列数与模板不一致"问题**：表格由 Excel 动态生成，列数天然等于 Sheet 列数。

#### FR-4：模板管理
- 支持从现有模板**复制**新建，复制时**绑定关系默认一并复制**，用户可在新模板上继续增删/修改绑定；
- 一个模板可维护一套 Sheet 清单（骨架），不要求每个 Sheet 都有数据；
- 模板按控制表/函证类型管理，支持复用。

#### FR-5：双模式并存兼容
- 现有 Output 函数/{{变量}}模板**完整保留**，可继续使用；
- `{{变量}}`（项目编码、项目名称等基础信息字段）通过**点击右侧"控制表函数"面板**在模板上生成映射码的机制**保留并优化**；
- 支持**模板内混用** Output 表格 + Excel 直填表格（同一 Word 中，一个表格用 Output，另一表格用拖拽的 Sheet）；
- 制函入口跟随模板类型，不设全局模式开关。

#### FR-6：模板占位可视化与绑定交互（OnlyOffice）
- 模板中**未被绑定的表格位置**，以**虚线边框的虚拟表格占位**呈现；
- 未绑定/悬停时，用**半透明浅色**标注，并显示"请拖入 Sheet 或插入 Output"的提示；
- **绑定后用颜色区分来源**：
  - **浅蓝色** = 已绑定 Excel Sheet；
  - **浅黄色** = 使用 Output 函数；
  - **虚线/半透明** = 未绑定；
- 占位块提供快捷入口（点击可"绑定 Sheet"或"插入 Output"）；
- 已绑定表格保留一个"来源标记"小角标，便于识别数据来源。

#### FR-7：列宽控制与排版/分页规则
**列宽**：
- **表格总宽度 = 函证模板整体文本宽度**（无论几列，总宽对齐文本区，不超出）；
- 列内分配：默认按列数均分铺满文本宽；允许在 OnlyOffice 中微调各列宽度比例；
- **不存在"列数与模板不一致"问题**：表格由 Excel 动态生成（见 FR-3），列数=Sheet 列数。

**表格插入后的文档流动**：
- 表格在**占位锚点位置就地展开**，其后的文档内容（标题/其他表格/盖章区）**自动向下移动**（流式排版，非绝对定位）；
- 保证插入表格后，后续内容不被覆盖，自动跟随后移。

**表格跨页处理**：
- **守住底线：单元格不可跨页拆分**——尤其高度较高的单元格保持完整，不在单元格内部拆开；其余排版无限制；
- **跨页自动重复表头行**（Word"标题行重复"属性）；
- 表格与其前标题尽量**同页**（"与下段同页"属性），避免标题在页尾、表格在页首；
- 跨页时若函证规范要求，**提示用户人工处理骑缝章**（系统不自动识别/标记）；
- 跨页不影响每行宽度，仍锁定模板文本宽。

#### FR-8：边界与异常处理

| 场景 | 处理策略 |
|----|----|
| **函证未上传 Excel** | 制函时该函证跳过 Excel 直填部分；若模板要求必须有 Excel 直填数据，则提示"该函证未上传 Excel" |
| **Sheet 无数据 / 空表** | 渲染时跳过该 Sheet 位置（不产生空表） |
| **绑定的 Sheet 在函证 Excel 中不存在** | 提示"绑定关系中的 Sheet 在函证 Excel 中未找到"，并跳过该位置，不阻断其他绑定渲染 |
| ~~Excel 列数与模板绑定不一致~~ | **不存在此场景**：表格由 Excel 动态生成（FR-3），列数=Sheet 列数 |
| **Excel 文件损坏 / 无法解析** | 制函失败并明确报错，不影响其他函证 |
| **绑定关系缺失 / 模板未配置** | 制函时按 Output 模式兜底（若模板是 Output 模板），或提示用户先配置绑定 |
| **并发制函** | 批量制函时各函证独立渲染，单函证失败不影响整批其他成功项 |

## 四、非功能需求

| 类别 | 需求 |
|----|----|
| **兼容性** | 保留所有现有 Output 模式功能，不回归 |
| **易用性** | 新用户无需接触任何代码/函数即可完成 Excel 直填制函 |

## 四-A、与现有系统的衔接（技术落地要点）

> 本节说明新方案如何在现有技术栈上落地，避免推倒重来。基于对现有源码的分析（详见 5.3）。

| 环节 | 现有实现 | 新方案衔接 |
|----|----|----|
| **模板在线编辑/预览** | `@onlyoffice/document-editor-react` + iframe 操作（`OnlyOfficeWrapper.js`） | 复用现有 OnlyOffice 集成，扩展占位/着色/绑定交互 |
| **字段插入通道** | `handleInsert(identifier)` → `ascWindow.insertText()` | 复用该通道，扩展为"拖拽 Sheet 到表格"或"点击绑定" |
| **制函渲染** | **Poi-tl**（`XWPFTemplate` + `LoopRowTableRenderPolicy`）+ `WordToPdfUtil` | 复用 poi-tl 管线，新增"Excel Sheet 注入模板表格位置"逻辑 |
| **模板存储** | 模板表 + OnlyOffice 文档服务器 | 复用现有模板表，新增"模板-Sheet 绑定"表 |
| **批量制函** | `ConfirmMakeController.createBatchConfirm` → 逐函证生成 | 复用批量制函入口，Excel 直填模板走新增渲染逻辑 |

**需要新增的模块**：
1. **Excel 多 Sheet 解析器**（读取函证 Excel，解析表头/数据/多 Sheet）；
2. **绑定关系存储与接口**（模板级"Sheet↔模板表格"绑定 CRUD）；
3. **Sheet 注入渲染逻辑**（poi-tl 插件/策略：在绑定位置把 Sheet 数据渲染成 Word 表格）；
4. **OnlyOffice 绑定交互扩展**（占位可视化 + 拖拽/点击绑定）。

**不需要新增/改造**：不 clone 改 OnlyOffice 源码、不引入新文档引擎、不弃用现有 Output/poi-tl 管线。

### 5.3 OnlyOffice 技术可行性调研（2026-08-18，针对待确认项 10）

**结论：占位可视化 + 拖拽绑定在现有 OnlyOffice 集成上可行，且已有可复用的技术基础。** 依据为对现有系统源码的直接分析（未 clone 全量 OnlyOffice 源码，因为系统已深度集成）。

**现有集成证据（源码分析）**：
1. **前端用官方 React 组件** `@onlyoffice/document-editor-react`（`OnlyOfficeWrapper.js`），嵌入方式为标准 DocsAPI。
2. **已深度访问编辑器内部**：
   - `findAscIframe()` 查找 `iframe_asc.*` 核心编辑 iframe；
   - `findMainEditorIframe()` 查找 `frameEditor`；
   - `onDocumentReady` 直接通过 `mainIframe.contentWindow.document.querySelector` 操作编辑器 DOM（隐藏 logo、编辑按钮、改 tab 样式）。
3. **已实现"点击字段→插入模板"**：模板设计页右侧字段面板 → `onTableRowClick` → `handleInsert(identifier)` → `ascWindow.insertText(value)`。这说明**已打通"外部 UI 注入内容到 OnlyOffice 编辑器"的通道**。
4. **制函渲染管线已明确**：后端用 **Poi-tl（`XWPFTemplate` + `LoopRowTableRenderPolicy`）** 渲染 Word 模板 → `WordToPdfUtil.wordToPdf` 转 PDF（`ConfirmMakeServiceImpl.java`）。模板中 `Output()`/`{{}}` 由 poi-tl 解析。
5. **官方插件机制可用**：README 提到 connector 放容器 `sdkjs-plugins` 目录，可开发自定义插件扩展编辑器能力。

**对"占位可视化 + 拖拽绑定"的技术判断**：

| 能力 | 可行性 | 实现路径 |
|----|----|----|
| **虚拟表格占位 + 半透明标注** | ✅ 可行 | 利用**表格底色/边框样式**模拟占位（半透明浅色 = 单元格底色），或开发**官方插件**注入占位元素 |
| **绑定状态着色（Sheet=蓝/Output=黄）** | ✅ 可行 | 通过 iframe 内 DOM 操作（现有 `onDocumentReady` 已验证该通道）给表格加底色/角标 |
| **拖拽绑定交互** | ⚠️ 需定制 | 参考现有"右侧面板点击插入"模式，改为"右侧 Sheet 列表拖拽到表格上"；需在 OnlyOffice 文档上监听拖放，或通过外部面板 + 定位插入实现 |
| **绑定关系存储与制函渲染** | ✅ 可行 | 绑定关系存 DB（模板级）；渲染时后端读绑定 → 用 poi-tl 在模板对应表格位置填充 Excel Sheet 数据（**poi-tl 本身支持表格行渲染，见 `LoopRowTableRenderPolicy`**） |
| **表格宽度=模板文本宽** | ✅ 可行 | poi-tl / Word 表格可设百分比宽度（现有 `HtmlToDocxConverter` 已用 `PCT` 宽度） |

**关键结论**：
- **不需要 clone 全量 OnlyOffice 源码**，现有集成已提供足够扩展点；
- 占位/着色/绑定**前端交互**主要靠"iframe 内 DOM 操作 + 官方插件机制"，与现有 `handleInsert`/`onDocumentReady` 模式一致；
- **制函渲染**不依赖 OnlyOffice 编辑器本身，而是走后端 **Poi-tl 渲染管线**，只需新增"Excel Sheet 数据注入到模板表格位置"的渲染逻辑；
- **最大待验证点**：OnlyOffice 编辑器内"拖放"事件的捕获与落点定位（若 OnlyOffice 限制跨域 DOM 事件，可退化为"右侧面板点击 → 定位到当前光标/选中表格绑定"）。

## 附录 A：docx→Markdown 实测记录（选型依据）

**结论：已否决 Markdown 方案，统一 OnlyOffice。** 实测要点：
- 用 `docx2markdown`（v0.1.1）转换「往来函证模板（销售、采购）.docx」；
- 内容/数据层还原度较高（8 表、Output 函数、{{变量}} 基本保留）；
- 但**宽表（列多）转换效果不佳**、个别表格在 md 预览中不完整、表头软换行被拆行、连续加粗标记被拆分；
- 因此若以 Markdown 作为制函格式或绑定依据，存在失真风险 → 决定**彻底取消 Markdown，统一 OnlyOffice**，规避一切转换失真。

实验产物：`../code/conversion_test/template_from_docx2markdown.md`、`convert_test.py`。
